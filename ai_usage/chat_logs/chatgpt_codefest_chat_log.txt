================================================================================
FINAL SYSTEM ARCHITECTURE
================================================================================

The final Track 1C workflow is:

1. Receive a user question.
2. Planner determines the initial search direction.
3. Retrieval searches the Ashen Era corpus.
4. Voyage AI creates query embeddings.
5. ChromaDB retrieves semantically related chunks.
6. Reranking improves evidence relevance.
7. Evidence checker determines whether information is sufficient.
8. If insufficient, query rewriting produces a refined search.
9. The cycle repeats until sufficient evidence is found or the search limit is reached.
10. The answer generator produces a grounded response.
11. Search steps and sources are returned in structured form for evaluation and traceability.

================================================================================
KEY TECHNICAL DECISIONS
================================================================================

- Iterative search was chosen because Track 1C requires reasoning between searches.
- Planner, retrieval, evidence checking, query rewriting, and answer generation were separated
  for maintainability and testing.
- Voyage AI was used for semantic embedding/reranking support.
- ChromaDB was used as the vector store.
- API secrets were kept in local environment files and excluded from Git.
- Evaluation results were stored as JSON for traceability.
- The system was designed to report uncertainty rather than hallucinate unsupported answers.
